# ADR 0002. Код публічний, вміст приватний

**Статус:** прийнято, 2026-10-08

## Контекст

Репозиторій публічний. Водночас система працює з персональними даними власника:
контакти, текст резюме, перелік компаній, куди він подавався, і статуси цих
подач. Частина цих даних шкідлива в публічному доступі — зокрема перелік
відмов.

## Рішення

**Рушій — у git. Вміст — ні.**

| У репозиторії | Поза репозиторієм |
| --- | --- |
| адаптери джерел, дедуплікація, скринер, API, шаблони | `.env`, вміст БД, `data/` |
| схема БД і міграції | значення фактів, текст булетів резюме, контакти |
| `.env.example`, фікстури з вигаданим кандидатом | реальні подачі та їх статуси |

Перевірка в CI: пошук по дереву телефону, пошти й доменів власника. Збіг —
збірка падає.

## Наслідок, який виявився перевагою

Щоб рушій працював без вмісту, він мусить бути узагальненим: профіль кандидата
стає рядком у БД, а не константою в коді; резюме — даними, а не захардкодженим
текстом. Через це проєкт перетворюється з «резюме Сергія» на інструмент, що
запрацює в будь-кого після `docker compose up`.

Тобто вимога безпеки збіглася з вимогою якості — рідкісний випадок, коли
обмеження робить архітектуру кращою, а не гіршою.
